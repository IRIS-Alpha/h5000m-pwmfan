## 新增的界面改进提案

以下是本轮新增的设计要求或提案，先进入核查和设计待办；除明确标注外，尚不视为已冻结的实现规范。

### 顶部区域

- 主题与语言切换统一为同类紧凑交换器：主题选项为“自动 / 亮 / 暗”，语言选项为 `CN / EN`，参考用户提供的 [21st.dev Theme Switcher](https://21st.dev/@ncdai/components/theme-switcher-1) 视觉。
- 状态栏改为左侧紧凑标题“风扇控制”和“运行中”状态，状态指示宽度贴合文字；主题与语言切换放在右侧。具体移动端断点和控件压缩规则待视觉核查。

### 模式选择与状态

- “快速调度”改称“模式选择”；删除“控制来源 · 插件”和底部近 24 小时/本次开机保护统计行。
- “固定请求”和“曲线预设”互斥选择时，由整个模式容器体现选中状态，而不是只高亮内部子项；参考用户提供的 [Border Beam Panel](https://21st.dev/@rmahammad/components/border-beam-panel)，并用绿色/红色指示状态。
- 需核查 `已选 / 未选 / 待应用` 三种状态如何映射到真实配置提交流程；边框流光与状态颜色不能替代可读文本或可访问状态。

### 固定请求、滑块与提示

- 固定请求区拟改为标题/状态行、占空比标签行、带 `− / +` 按钮的滑块行；加减和滑块均按 1% 步进，保留吸附效果。滑块不再显示尾随百分比，拇指显示随滑块移动的浮动读数。参考 [P Slider](https://21st.dev/@coss.com/components/p-slider-14) 与 [Slider](https://21st.dev/@kuratlielia/components/slider)；需核查窄屏、键盘和读屏可用性。
- 新方案拟移除独立“停转”按钮，让固定请求可直接设为 0%；曲线也可在部分温区设置为 0%。这与 V3 已确认的“固定请求 10% 起步、用独立停转动作表达 0%”冲突，暂不改正式需求，需先核对控制后端的 0% 语义和全局保护仲裁。
- 模式选择标题行计划按条件显示提示：右侧黄框“高温区曲线过低”和红框“停转”，中间显示“过高的温度可能影响设备硬件寿命”；未触发时隐藏。用户提供的开发预览判据为低温区 `<40°C`、高温区暂定 `≥60°C`、高温区输出 `<50%`，并要求开发预览暂时强制显示便于检查。上述温区是预览判据，不是固件控制阈值；红色“停转”提示的精确触发条件仍需确认。

### 折叠参数与图表

- 定温驱动、自定义曲线和温度历史的折叠参数区域存在文字排版、基线和视觉对齐问题，需统一标题、状态、折叠箭头与内容间距。
- 曲线图本身暂未提出整体重做；优先检查温度历史图底部的窗口/采样设置排列、字段宽度和单位间距。

### LuCI 操作与高级设置

- 仪表盘缺少 LuCI 的“重置 / 保存 / 保存并应用”操作区；需核查当前页面表单封装、未保存状态提示和移动端工具栏遮挡问题，再确定集成方式。
- 高级设置新增“模式最小应用间隔”，提出的默认值为 3 秒；需厘清它是模式切换冷却、连续请求节流还是延迟合并，以及它与固定请求是否延迟 3 秒的关系。
- 高级设置文字和分组视觉干扰较多；目标是建立可复用的标题、说明、字段和危险/状态提示模块样式，并与主页保持一致。

## 下一轮待核查与待讨论事项

- 各项调度变更当前是立即写入并生效，还是先暂存、点击 LuCI“应用”后生效？“保存”和“保存并应用”分别应覆盖哪些配置？
- 连续快速切换模式是否已有最小生效间隔或竞态保护？若新增 3 秒值，应拒绝中间请求、延迟最后一次请求，还是只防止重复点击？
- 固定占空比变化应立即响应、固定延迟 3 秒，还是由高级设置的应用间隔统一节流？
- 建议逐项区分即时预览、即时生效、延迟/合并生效及保存后生效的设置；模式选择、滑块拖动、曲线编辑、历史图窗口/采样设置、控制来源和安全参数不可假定采用同一策略。
- 新滑块允许 0% 后，曲线 0% 与固定请求 0% 是否都代表停转请求？全局温度保护和内核高温区能否覆盖它们？用户要求的两个警示应由哪些精确条件触发？
- `待应用` 状态应指 LuCI 配置尚未提交、提交后服务尚未确认，还是请求因 3 秒间隔等待执行？需基于真实状态来源定义，不能只做视觉状态。
