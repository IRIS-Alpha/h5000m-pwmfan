# H5000M PWM Fan 需求改进

> 当前界面需求以 [第三版修改需求](REQUIREMENTS_V3.md)（2026-11-19）为准；本文保留历史决策，冲突条目由 V3 覆盖。

本文记录 LuCI 界面的改版要求，作为后续前端、UCI 字段和状态接口调整的共同依据。结构采用主页加高级设置子页面；主页聚焦运行状态和曲线分析。

## 1. 问题与原因

### 1.1 简体中文没有生效

当前仓库有 `po/zh_Hans/h5000m-pwmfan.po`，但翻译能否显示取决于两个运行时条件：

- APK 构建必须同时生成并安装 `luci-i18n-h5000m-pwmfan-zh-cn`；只安装主包不会安装 `.lmo` 目录。
- `luci.main.lang` 必须为 `zh_cn`，或者用户在页面中选择简体中文后成功写入该值并重新加载。

本次 replay 使用的是英文自动语言环境，且录制固件没有安装本包的 `.lmo`，因此出现英文是预期结果，不代表 PO 文件已经被 LuCI 使用。改版验收必须在安装翻译 APK 后分别验证 `auto`、`zh_cn` 和 English。

### 1.2 顶部信息重复

初版顶部指标和“温控阵列”重复显示温度，也没有把输出和保护状态分成用户可理解的组。改版只保留一个顶部摘要区，由两个外置容器组成：温度阵列、转速/输出阵列。页面下方不再重复温度卡片。

### 1.3 快速模式重复且宽度不稳定

“Custom curve”和“Manual”同时出现，用户无法理解两者区别。改版把“手动”定义为可编辑曲线模式，删除固定 `manual_pwm` 控件和独立的 Custom 按钮。快速模式固定为六项：

1. 安静
2. 平衡
3. 性能
4. 手动
5. 内核
6. 关闭

六个按钮在桌面端等宽排列，在窄屏按 3 列或 2 列等宽网格换行；按钮不能因文字长度改变宽度。

### 1.4 曲线编辑能力不足

“Balanced curve”作为表单字段暴露了实现细节，却不能直接编辑曲线。改版在快速模式下方放置可视化曲线编辑器。安静、平衡、性能是只读预设；用户拖动、增加、删除或修改任一点后，曲线复制到手动曲线并自动切换到“手动”。

### 1.5 PWM 原始值对普通用户不友好

`128 / 255`、`Controller target` 和 `Hardware read-back` 是工程诊断信息，不应在主要视图重复出现。主要界面统一显示百分比，原始 PWM 只在诊断折叠区保留一次。

### 1.6 Fan policy 过长

当前表单将模式、曲线、保护、启动助推、回差和采样参数连续堆叠。改版把常用控制留在主页，把策略参数移至高级设置子页面，并按迟滞降档、启动助推、故障全速等逻辑分类；所有输出字段使用百分比。

## 2. 改版页面结构

设置两个页面：默认主页和高级设置。除高级设置外不再拆分其他标签页。

```text
H5000M PWM Fan                         [语言]
├─ 主页
│  ├─ 温度阵列（顶部摘要容器）
│  ├─ 转速/输出阵列（顶部摘要容器）
│  ├─ 快速调度（六个等宽按钮）
│  ├─ 转速曲线（图表 + 可编辑点）
│  ├─ 温度监控滚动曲线
│  └─ 可选风扇动图（复用仓库内合适素材）
└─ 高级设置
   ├─ 内核保护
   ├─ 迟滞降档
   ├─ 启动助推
   ├─ 故障全速
   └─ 其他策略与诊断
```

### 2.1 温度阵列

温度项来自运行时传感器注册表，不硬编码为一定存在的节点。优先显示以下语义名称：CPU、射频、5G 模组、PHY；不存在时显示“不可用”，并保留状态原因（缺失、过期、无效、不支持）。

每项显示：名称、摄氏温度、数据状态、是否被曲线选用。所有有效传感器仍参加最高温保护，曲线来源可以是自动最高温或用户选择的单个来源。

### 2.2 转速/输出阵列

主要字段改为百分比：

- 请求输出：当前策略请求的占空比百分比。
- 实际输出：写入后从 hwmon 回读的占空比百分比。
- 保护输出：当前保护下限百分比；触发保护时显示“保护接管”。
- 其他参数：当前模式、控制所有者、RPM 反馈状态、最近一次原因。

如果硬件提供 tach/RPM 节点，可以在“其他参数”增加真实转速；当前包只有 PWM 回读，不能把 PWM 百分比冒充物理 RPM。没有 RPM 时必须显示“无 RPM 反馈”。

### 2.3 快速调度

六项按钮使用同一尺寸、同一层级和 `aria-pressed` 状态。模式语义如下：

- 安静、平衡、性能：加载对应只读预设曲线。
- 手动：使用用户编辑的曲线；不再出现单独的固定 PWM 输入。
- 内核：停止用户态 PWM 写入，只显示内核当前回读和保护状态。
- 关闭：关闭本包控制，执行既定释放/故障策略；当内核保护开关启用时禁止点击。

关闭与内核模式都不能关闭 CPU passive、hot、critical 等内核保护。禁用用户态控制时仍显示状态和传感器信息。

## 3. 曲线控制规格

- 曲线横轴为温度（°C），纵轴为输出百分比（0–100%）。
- 安静、平衡、性能预设只能通过“恢复预设”替换当前手动曲线，不直接展示为三个长表单字段。
- 手动曲线至少包含两个点；温度严格递增；输出百分比范围为 0–100%。
- 支持拖动已有点、增加点、删除点、输入点值和恢复预设。
- 任意手动调整立即把快速模式切换为“手动”，但不自动写入设备；保存/应用仍是明确动作。
- 图表显示当前温度的竖向参考线、当前实际输出的横向参考线，以及保护输出的横向参考线。保护线使用醒目但兼容明暗主题的警示色。
- 当前实际输出应来自 hwmon 回读；回读不可用时显示“不可用”，不能使用请求值代替。

建议后端继续使用 PWM 0–255 存储和计算，UI 在读写时转换为百分比；转换采用四舍五入，并在高级诊断中显示原始值。

## 4. 内核保护规格

保护区单独成列/容器，至少包含：

- 启用保护：默认启用。
- 保护转速：20%、30%…100%，10% 步进，默认 20%。
- 当前保护状态：正常、保护接管、内核模式或不可用。
- 说明和取消警告：关闭保护必须二次确认，并明确允许关闭后“关闭”模式可能停止用户态风扇控制。

保护启用时：

- 任何曲线点和手动输出不得低于保护转速。
- “关闭”按钮不可用，并给出原因。
- 高温、传感器故障、5G 热节流等更高优先级保护仍可将输出提升至更高值或 100%。

这里将用户原文中的“未弃用”按“未启用保护”理解；实现前若该词有其他含义，需要在后端契约中改名，避免出现双重否定。

## 5. 参数分组与百分比化

### 主页

主页仅放常用运行信息和操作：温度摘要阵列、输出摘要阵列、六种快速模式、可编辑风扇曲线、温度监控滚动曲线。语言选择仍可放在页面标题栏。内核保护与 Fan policy 参数移至高级设置子页面。

### 高级设置

将 Fan policy 内容按行为逻辑分组：内核保护、迟滞降档、启动助推、故障全速、其他控制参数与诊断。删除 `manual_pwm` 和可直接编辑的 `curve_balanced` 字段显示；曲线编辑留在主页。

### 传感器清单（后期扩展）

在高级设置或独立子页面提供可发现传感器列表，列出传感器名称、来源、当前读数、有效性与更新时间；允许用户重命名、启用/停用并选择是否映射到主页摘要阵列。此项属于后期泛化改进，首版仍使用已确认的 H5000M 传感器注册表。

## 6. 简体中文验收

- 构建主包和 `luci-i18n-h5000m-pwmfan-zh-cn`，在目标固件上同时安装。
- 将 `luci.main.lang` 设置为 `zh_cn`，刷新后页面标题、六个模式、两个顶部容器、保护说明、曲线提示和表单字段均显示中文。
- 切换回 English 后刷新，所有字符串恢复英文。
- `auto` 模式跟随 LuCI 全局语言，不由本包单独覆盖。
- 如果翻译 APK 未安装，语言选择器不显示“简体中文”，并给出“未安装语言包”的可诊断状态。

## 7. 验收标准

- 页面包含主页和高级设置两个页面；主页只出现一个温度阵列和一个输出阵列，顶部不再重复同一批温度。
- 快速调度恰好六项，桌面和移动端等宽，无“Custom curve”或固定 `Manual PWM` 按钮。
- 调整曲线点会切换到手动模式，图表同时显示当前实际输出线和保护输出线。
- 保护启用时不能保存低于保护转速的曲线，也不能启用关闭模式；关闭保护必须确认。
- 主要用户界面不显示 `128 / 255` 等原始表达；原始值只出现一次于诊断区域。
- 所有输出显示在 0–100% 范围，实际输出来自回读值；无 RPM 时明确标识无反馈。
- Vantage light、dark、auto 和 390px 视口均无横向溢出或固定工具条遮挡内容。
- 温度监控图和风扇曲线图底部均有滚动范围、读取间隔（秒）、启用/关闭三个设置；切换图表关闭不能停止控制器必需的传感器读取或安全保护。
- 高级设置按迟滞降档、启动助推、故障全速等逻辑分类，百分比类输出参数统一使用百分比控件。
- 相关 UCI、状态文件、控制器校验和 Bats 测试同步更新后，APK 构建和现有严格检查全部通过。

## 8. 需要在实现前确认的事项

1. “手动”是否确认代表“可编辑曲线”，而不是固定占空比模式。
2. H5000M 是否存在可稳定读取的 tach/RPM 节点；若没有，页面统一使用“实际输出占空比”。
3. “射频”和“PHY”对应的具体 hwmon/thermal 节点名称及缺失时的展示文案。
4. 保护开关关闭后的行为是否允许用户态“关闭”模式，还是始终保留最低保护输出。
5. 保护转速默认 20% 是否已通过硬件实测确认，还是仅作为 UI 初始值。

## 9. 当前固件风扇插件数据清单

2026-11-17 通过路由器 LuCI 只读页面确认，当前运行插件是 `luci-app-h5000m-fancontrol`，页面节点为 `admin/system/h5000m_fancontrol`，状态命令为 `/usr/sbin/h5000m-fancontrol-status`。本包应以它作为行为和数据来源参考，不直接复制其实现。

### 9.1 当前状态接口返回

状态接口目前返回以下字段：

- 策略：`enabled`、`mode`、`curve`、`curve_data`、`temp_source`。
- 参数：`manual_pwm`、`interval`、`hysteresis`、`down_delay`、`start_pwm`、`start_boost_ms`。
- PWM：`pwm`、`pwm_value`、`requested_pwm`、`target_pwm`、`applied_pwm`。
- 风扇反馈：`fan`、`fan_feedback`、`fan_rpm`。
- 温度：`cpu_temp/cpu_label`、`phy_temp/phy_label`、`wifi1_temp/wifi1_label`、`wifi2_temp/wifi2_label`、`module_temp/module_label`、`control_temp/control_sensor`。
- 保护：`module_therm`、`modem_floor`、`thermal_floor`、`thermal_state`、`thermal_max_state`、`thermal_owner`。
- 结果：`result`、`reason`、`state_age`。

实时只读快照显示：启用、`manual` 模式、请求/回读 PWM 为 51/255（20%），CPU 53°C、PHY 47°C、两路 Wi‑Fi 38°C、5G 模组 42°C、无 RPM 反馈，`thermal_floor=128`、`thermal_state=1/3`、`thermal_owner=shared`。

### 9.2 读取的数据源

插件代码会访问以下设备数据：

- `/sys/class/thermal/thermal_zone*/type`、`temp`、`policy`、`available_policies`：CPU/SoC 温度和 thermal governor。
- `/sys/class/hwmon/hwmon*/name`、`temp1_input`、`pwm1`、`fan*_input`：CPU/PHY/无线温度、PWM 写入/回读和可选 RPM。
- `/sys/class/net/ra0`、`rai0` 配合 `iwpriv ... stat` 的 `CurrentTemperature`：无线驱动没有 hwmon 时的射频温度备用来源。
- `/sys/class/thermal/cooling_device*`、设备树 `pwm-fan/cooling-levels` 和 `thermal-zones/*/cooling-maps/*`：内核风扇保护状态、最大状态和保护映射。
- `/tmp/5gmodem/tele.json`、`/var/run/mt5700m/temperature` 及兼容缓存：5G 温度和热节流级别。
- UCI `h5000m_fancontrol.settings`：模式、曲线、手动输出、采样间隔、回差、降速延迟、启动助推和故障输出。

页面本身主要调用 `uci.get` 和 `file.exec`；状态查询不应写入 UCI、PWM、thermal policy 或服务状态。

### 9.3 必须修正的安全一致性

当前快照同时报告 `thermal_floor=128`（50%）和 `applied_pwm=51`（20%）。新包不能只展示其中一个值，必须分别显示“策略请求”“内核保护下限”和“硬件实际回读”，并在保护下限高于实际回读时标记为异常、阻止降低曲线或进入关闭模式，直到确认内核/驱动的实际所有权语义。

## 10. 温度滚动曲线

### 10.1 目标

在同一页面提供温度历史和输出关联图，用户调整风扇曲线后可以直接观察温度变化，不再依赖 SSH、脚本或其他监控插件。

### 10.2 传感器选择

- 复用状态接口已经识别的传感器：CPU、PHY、Wi‑Fi 射频 1、Wi‑Fi 射频 2、5G 模组。
- 以可用传感器动态生成多选项；缺失、过期、无效或不支持的传感器显示原因并不能勾选。
- 默认勾选 CPU，并在页面提供“一键选择全部可用传感器”。
- 采集层只读取一次传感器快照，同时供控制器、顶部摘要和图表使用，避免页面打开后重复调用 `iwpriv` 或 modem 文件。

### 10.3 时间范围和采样

- 时间范围提供 5 分钟、15 分钟、30 分钟、1 小时和 6 小时；默认 15 分钟。
- 采样间隔默认跟随控制间隔，允许在高级设置中独立设置 2–10 秒；不得为了图表把硬件读取频率提升到不可控水平。
- 后端维护有上限的环形 JSONL/内存队列，记录 `timestamp`、各温度、请求输出、实际输出、保护输出、模式和保护原因。
- 重启后历史清空并显示明确空状态；第一阶段不把高频数据写入闪存。后续若要跨重启保存，必须单独设计采样压缩和存储策略。
- 页面只读获取历史，曲线编辑和保存不能清空历史。

### 10.4 图表交互

- 横轴为本地时间，左纵轴为温度 °C；每个已选传感器一条可区分的线。
- 请求输出、实际输出和保护输出以百分比叠加在右纵轴，提供开关控制显示/隐藏。
- 显示当前时刻参考线、悬停提示、数据状态和最近一次保护原因。
- 传感器不可用时断线显示，不把缺失值绘制为 0°C。
- 明暗模式使用 Vantage 主题变量，颜色和网格线在两种主题下都保持可读。

## 11. 风扇曲线纵轴改进

- 曲线纵轴从原始 PWM 0–255 改为用户可理解的输出百分比 0–100%。
- 预设曲线和手动曲线的存储仍可使用 PWM 或百分比，但 API 必须明确单位，禁止同一字段混用。
- 图表标签使用“风扇输出（%）”；只有确认存在 `fan*_input` 且读数有效时，才额外显示“实际转速（RPM）”。
- 当前固件没有 RPM 反馈，因此第一阶段不能把 PWM 百分比命名为真实转速；应显示“实际输出”或“风扇输出百分比”。
- 保护输出线必须独立于曲线，且在请求低于保护下限时明确显示保护接管或异常状态。

## 12. 新增验收标准

- 从一个状态快照同时生成顶部摘要、温度滚动曲线和曲线图标记，三者的时间戳和数值一致。
- 选择 CPU、PHY、Wi‑Fi、5G 中任意组合并切换 5 分钟至 6 小时范围，页面无横向溢出，缺失数据不伪造为零。
- 采样不会修改 UCI、PWM、thermal policy 或服务状态；退出页面不停止采集服务。
- 图表能同时区分请求输出、实际回读和保护下限；当三者矛盾时显示警告而不是静默覆盖。
- 真实设备无 RPM 时不显示虚假的 RPM 数值；有 tach 节点时才显示 RPM 并标注来源。
- 当前固件的 `thermal_floor=128`、`applied_pwm=51` 这类矛盾必须在硬件验证中解释并覆盖测试。

## 13. 页面拆分、图表控件与动效

### 13.1 主页和高级设置

- 默认进入主页，主页只呈现两组顶部摘要阵列、六种快速模式、可编辑风扇曲线和温度监控滚动曲线。
- Fan policy 与保护/诊断参数移到第二页面“高级设置”，避免挤占常用操作区域。
- 不再继续拆分子页面；传感器清单属于后期扩展，届时优先放入高级设置，只有列表规模或交互复杂度明显增长时才考虑单独子页面。
- 两页面共享同一份状态快照，切换页面不触发重复硬件采集或控制器重启。

### 13.2 图表底部设置

温度监控图和风扇曲线图各自在图表底部放置三个紧凑下拉框；温度传感器选择放在温度图标题旁，不占用这三个底部设置：

1. 滚动范围：可选 5 分钟、15 分钟、30 分钟、1 小时、6 小时；默认 15 分钟。
2. 读取间隔：以秒为单位，提供受控选项（例如 2、5、10 秒）；默认跟随控制器采样间隔。
3. 图表：启用/关闭，控制该图表的历史采集与绘制。

温度图和风扇图可分别选择范围与刷新间隔，但底层共享一次传感器/控制状态快照。关闭图表只关闭图表历史功能，不影响风扇控制、故障检测、温控保护和顶部实时摘要。读取间隔不得快于硬件接口允许的频率；实际采样频率由后端统一限流，不能由多个页面控件叠加触发轮询。

风扇曲线图仍保留温度到输出百分比的可编辑静态曲线。滚动范围用于叠加当前工作点/输出历史轨迹，不改变曲线本身的坐标定义；读取间隔用于更新工作点和历史轨迹。这样两个图表拥有一致的底部控件，同时不会把策略曲线误做成时间序列图。

### 13.3 高级设置分类

- 内核保护：启用状态、保护输出下限、当前接管状态及关闭保护的确认说明。
- 迟滞降档：温度/输出回差、降速等待时间和避免频繁升降速的行为说明。
- 启动助推：启动输出百分比、持续时间及适用条件。
- 故障全速：传感器无效/过期、控制器异常和通信故障时的全速策略、触发原因及恢复条件。
- 其他策略与诊断：采样周期、温度源、设备路径、原始 PWM 和状态年龄等低频或工程信息。

分组标题使用面向行为的语言，解释参数影响；不将 shell 字段名或原始寄存器值直接作为主要标签。

### 13.4 风扇动图

- 检查仓库及相关本地 LuCI 项目是否已有许可清楚、体积合适的风扇动图素材；优先复用，避免新增不必要的大型资源。
- 动图仅作状态辅助，不承担转速读数或风扇运行证明；动画状态应跟随有效输出/运行状态，状态未知时不伪造旋转。
- 尊重系统减少动态效果偏好；无合适素材时可以省略动图，不能为满足装饰要求牺牲首屏信息密度。

### 13.5 传感器清单后期范围

未来的传感器清单需要聚合已识别 thermal zone、hwmon、无线驱动和 5G modem 来源，显示来源路径、读数/单位、有效性、更新时间。重命名和主页摘要映射应存于本包 UCI，不得改变底层传感器标识或控制器安全仲裁。停用传感器只影响用户展示/曲线选择；若该传感器仍参与全源安全上限，界面必须明确说明，且不能因隐藏而绕过保护。
